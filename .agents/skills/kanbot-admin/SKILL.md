# kanbot admin

You are helping a human maintain kanbot, the board-driven agent team in this repo. Board agents (planner, implementers, reviewers, fixer) never use this skill.

## Map

| Path                       | What                                   | Edit?                           |
| -------------------------- | -------------------------------------- | ------------------------------- |
| `.kanbot/agents/<name>.md` | Agent definitions, the source of truth | Yes, then `kanbot sync`         |
| `.agents/skills/<name>/`   | Skills shared by all agents            | Yes                             |
| `.kanbot/config.yml`       | Daemon config; schema next to it       | Yes                             |
| `.kanbot/manifest.json`    | Template hashes from the last upgrade  | Never by hand                   |
| `.claude/`, `.codex/`      | Generated by `kanbot sync`             | Never; edit the source and sync |

`kanbot <command> --help` lists every flag. Agent frontmatter fields and output schemas: read an existing agent in `.kanbot/agents/` and copy its shape.

## Recipes

Finish every recipe with `kanbot sync` when agents changed, then `kanbot doctor`, then show the human the diff. The human commits and pushes; worktrees are made from the pushed base branch, so agents see nothing until then.

### Add or change an agent

1. Copy the closest existing agent. `name` must match the filename.
2. Column agents (`tier: column`) need an `output` schema; subagents (`tier: sub`) are reached through a column agent's `subagents`.
3. A new implementer also needs an entry under `implementers` in config and a matching `type:<x>` label on GitHub. Tell the human to create the label.
4. The body says _how_ to work. The daemon's prompt carries the task.

### Add a skill

1. Create `.agents/skills/<name>/SKILL.md` with `name` (matches the folder) and a `description` that says what it covers and when it applies.
2. Add the name to `skills` in each agent that should load it.

### Add a memory

When the human says "remember that …" or corrects something agents keep getting wrong, add a fact per `project-memory`. Stack, commands and conventions go in `project-conventions` instead.

### Upgrade kanbot

1. Run `bunx kanbot@latest upgrade --dry-run` and summarise it for the human.
2. Run `bunx kanbot@latest upgrade`.
3. Merge every `.kanbot-new` file (below).

### Merge `.kanbot-new` files

For each `<file>.kanbot-new` next to `<file>`:

1. Diff the two. Name each difference: the human's customisation, or kanbot's improvement.
2. Write the merged result into `<file>`: keep every customisation, take every improvement. Where they collide, ask the human.
3. Delete `<file>.kanbot-new`.

Done when `kanbot doctor` reports no unmerged `.kanbot-new` files and the human has seen a per-file summary of what was kept and taken.
